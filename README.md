# RouteForge: Multi-Delivery Route Planner

An Advanced Data Structures project. Given a road network, a warehouse, and a set of delivery
stops, it finds an efficient route that visits every stop.

- **Core (C++14):** weighted graph stored as an adjacency list, a hand-written indexed binary
  min-heap, Dijkstra's shortest paths, a nearest-neighbour tour, 2-opt optimisation, an exact
  Held–Karp benchmark, and BFS connected components. There are no external libraries.
- **Web app (Next.js 16 + React 19 + TypeScript):** dashboard, location/road/delivery
  management, an interactive Leaflet/OpenStreetMap map with an offline graph view, a
  route-comparison view, and an *Algorithm Lab* that replays Dijkstra step by step.

> **Studying the project?** Read [EXPLANATION.md](EXPLANATION.md). It explains every data
> structure, algorithm, and function, with worked examples and viva questions.
> The academic report sections are in [docs/REPORT.md](docs/REPORT.md).

## 1. Prerequisites

| Tool | Version | Check |
|---|---|---|
| Node.js | 20.9 or newer (tested on 24) | `node --version` |
| A C++14 compiler | g++ 6+ (MinGW on Windows, `build-essential` on Linux, Xcode CLT on macOS) | `g++ --version` |

No API keys, databases, or paid services are needed. Map tiles come from OpenStreetMap when
you are online. Without internet, use the **Graph view** toggle, which draws the same
network from the stored coordinates.

## 2. Run it

```bash
cd web
npm install            # install the web dependencies (first time only)
npm run engine:build   # compile the C++ engine -> engine/bin/route_engine(.exe)
npm run dev            # start the app at http://localhost:3000
```

`npm run dev` also builds the engine automatically if the binary is missing.

Production build: `npm run build && npm start`.

To use a different compiler: `CXX=clang++ npm run engine:build`.
To build with CMake instead: `cmake -S engine -B engine/build && cmake --build engine/build`.

## 3. Run the tests

```bash
cd web
npm run engine:test    # C++ unit tests (23 tests, ~15,000 checks)
npm test               # Vitest: validation, persistence, and C++ integration (31 tests)
npm run test:all       # both suites
```

## 4. Using the app

1. **Dashboard:** summary cards. Press **Calculate & optimise route**.
2. **Locations / Road Network:** add, edit, or delete vertices and edges (search and
   filters included). Validation runs in the browser and again on the server.
3. **Deliveries:** choose the warehouse, add or remove stops, mark them
   delivered, and change the settings (average speed, 2-opt move limit, round trip or one-way).
4. **Route Results:** NN vs 2-opt vs optimum, the legs, the NN steps, the 2-opt move log,
   and the distance matrix.
5. **Path Explorer:** the shortest path between any two locations, plus which locations are
   unreachable.
6. **Algorithm Lab:** step through Dijkstra with heap snapshots, the adjacency list, and
   complexity tables.

**Reset to demo data** (bottom of the sidebar) restores the sample Chennai network:
16 locations, 28 roads (one of them one-way), and one isolated depot to show
unreachability. Its distances are **illustrative**: straight-line distance × a road-type
detour factor, generated by `web/scripts/generate-demo-data.mjs`. They are not surveyed
road lengths.

Data is saved in `web/data/store.json`. Delete that file to start fresh from the demo data.

## 5. Project structure

```
engine/                     C++ core (all ADS logic)
  include/graph.hpp         adjacency-list graph
  include/min_heap.hpp      indexed binary min-heap (push / pop / decreaseKey)
  include/dijkstra.hpp      Dijkstra, path reconstruction, trace events
  include/route_optimizer.hpp  distance matrix, NN, 2-opt, Held–Karp, legs
  include/protocol.hpp      text request -> JSON response
  include/json_writer.hpp   tiny JSON writer
  src/*.cpp                 implementations + main.cpp (stdin -> stdout)
  tests/test_engine.cpp     dependency-free unit tests
web/                        Next.js application
  app/                      pages (/, /locations, /roads, /deliveries, /route, /explorer, /lab)
  app/api/                  REST endpoints (see below)
  components/               UI, map (Leaflet + SVG graph view), charts
  lib/engine.ts             spawns the C++ binary, serialises the graph
  lib/validation.ts         backend validation rules
  lib/store.ts              JSON persistence (atomic writes, demo reset)
  lib/service.ts            delivery service (business rules)
  data/demo_data.json       sample dataset
  tests/                    Vitest suites
docs/REPORT.md              report sections (abstract, architecture, results, ...)
EXPLANATION.md              full study guide
```

## 6. REST API

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/state` | all data (locations, roads, delivery, settings, last plan) |
| POST | `/api/locations` · PUT/DELETE `/api/locations/:id` | location CRUD |
| POST | `/api/roads` · PUT/DELETE `/api/roads/:id` | road CRUD |
| PUT | `/api/delivery` | set the warehouse `{warehouseId}` |
| POST | `/api/delivery/stops` · PATCH/DELETE `/api/delivery/stops/:id` | add, change status, or remove a stop |
| POST | `/api/delivery/reset` | clear all stops and the plan |
| PUT | `/api/settings` | `{averageSpeedKmh, returnToWarehouse, maxIterations}` |
| POST / DELETE | `/api/plan` | run the full pipeline / clear the result |
| POST | `/api/path` | `{source, target}` shortest path |
| GET | `/api/reach?source=ID` | reachable and unreachable locations |
| POST | `/api/trace` | `{source}` Dijkstra step trace |
| GET | `/api/graph-info` | adjacency list, density, components |
| POST | `/api/reset-demo` | restore the demo dataset |

Errors return `{error, fields}` with HTTP 400, 404, or 503.

## 7. Troubleshooting

| Symptom | Fix |
|---|---|
| `C++ engine not found` (503) | Run `npm run engine:build` and check that `g++` is on PATH. |
| `g++: command not found` | Install MinGW-w64 (Windows), `sudo apt install build-essential` (Linux), or `xcode-select --install` (macOS). |
| The map is grey or blank | No internet for tiles. Use **Graph view**. Every calculation still works. |
| You want the original data back | Sidebar → **Reset to demo data**, or delete `web/data/store.json`. |
| Port 3000 is busy | `npx next dev -p 3001` |
